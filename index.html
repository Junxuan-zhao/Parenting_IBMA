HALFpipe Task-Based fMRI Analysis Manual

Image-Based Meta-Analysis of Parenting Constructs and Emotion-Processing Brain Activity

Written by Junxuan Zhao .....

Adapted for the Parenting-IBMA project from the ENIGMA Task-Based fMRI Imaging Manual by Lea Waller, Susanne Erk, Henrik Walter, and Ilya Veer; the ENIGMA resting-state fMRI manual by Pozzi, Toenders, Veer, Waller, Haswell, Morey & Schmaal; and from the official HALFpipe documentation at fmri.science/halfpipe (About, Installation, and Manuals pages).

This manual assumes HALFpipe v1.3.2. Site-specific parenting-construct mappings, task contrasts, and analysis models referenced throughout are defined in your site's Site Confirmation Packet (Parenting Construct and fMRI Harmonization).

0. About This Manual

This manual walks each of the contributing sites in the Parenting-IBMA project through running HALFpipe on their local task-fMRI data, from data preparation through to the group-level summary statistics maps that will be pooled across sites for the image-based meta-analysis (IBMA).

  • The functional contrast at each site is an emotional-processing contrast (emotional stimuli/condition vs. a neutral or control condition), but the exact task, conditions, and contrast direction differ by site. These are documented per-site in your Site Confirmation Packet under fMRI Task Contrast.
  • The group-level model covariates are the 6 harmonized parenting constructs (Warmth/Responsiveness, Positive Reinforcement, Behavioral Control/Monitoring, Inconsistent Discipline, Psychological Control, Harsh/Reactive Control), which of these apply to your site, and which of your subscales map onto them, is documented per-site in your Site Confirmation Packet under Parenting Constructs and Analysis Models.

1. Prepare for Data Analysis

1.1 Hardware and Software Prerequisites

  • A computer with at least 8 GB of RAM.
  • At least ~0.6 – 1 GB of free disk space per subject for intermediate files, plus ~5.3 GB for the HALFpipe Singularity/Apptainer image (or ~23 GB if using Docker) and~500 MB for a working directory for one subject, one task, and one session.
  • Multiple CPU cores will speed up processing but are not required.
  • Running on a high-performance compute cluster (HPC) is recommended for larger sites and is faster/more resource-efficient.
  • A FreeSurfer license file needs to be located in the working directory.

1.2 Files Needed Per Subject

  1. Raw (non-skull-stripped) 3D T1-weighted anatomical image, .nii or .nii.gz. De-faced images work out of the box; if only skull-stripped anatomicals are available, see the note in step 5.5 below.
  2. Raw 4D functional (task) image, .nii or .nii.gz, for your site's emotion-processing task (see your Site Confirmation Packet, fMRI Task Contrast, for the task name and condition list).
  3. Field map images, if available (Siemens phase/magnitude pairs, Philips field-map + magnitude, or blip-up/blip-down AP/PA pairs), with their acquisition metadata (echo spacing, echo times, etc.).
  4. Event files with the onset and duration of every condition of your task, in SPM MAT, FSL 3-column, or BIDS TSV format. 
    Make sure event onsets are aligned to the acquisition of the first retained volume of your task run, especially if you discard initial volumes (see step 5.2, item 4).
  5. A group-level covariate spreadsheet (CSV, TSV, or XLSX) with one row per subject and the following columns:
    • ID - identical to the subject IDs used in your image file names.
    • Age (years).
    • Sex.
    • Your site's harmonized parenting construct score(s), using the exact subscale(s) confirmed in your Site Confirmation Packet (e.g., PBI-Care for Warmth/Responsiveness, APQ-Inconsistent Discipline, MAPS Physical Control for Harsh/Reactive Control, etc.). Only include the constructs your site actually contributes.
    • Any optional secondary-analysis covariates your site is using (race/ethnicity, parental education, SES, etc. See your study proposal and the Secondary analysis row of your Site Confirmation Packet model table).

1.3 Defining Your Task Contrast

Every site in the Parenting IBMA project is contrasting an emotional condition against a neutral/control condition, but the specific conditions differ by task. Using your Site Confirmation Packet's fMRI Task Contrast row for your site as a reference:

  1. Note the exact condition names in your event files that make up the “emotional” side of the contrast (e.g., angry/fearful/sad faces, negative images, “observe affect,” etc.) and the condition(s) that make up the neutral/control side (e.g., neutral faces, shapes, rest/baseline).
  2. Assign +1 to each emotional condition and −1 to each neutral/control condition, with 0 for any other conditions that are modeled but not included in the contrast. For the reverse contrast, assign −1 to each emotional condition and +1 to each neutral/control condition.
  3. Adjust the integers as needed so the contrast sums to zero — e.g., two conditions on one side and one on the other becomes [1 1 −2].
If you're unsure how to set up your contrast vector, contact the coordinating site before running HALFpipe.

1.4 Calculating Your High-Pass Filter Width

For each task condition, calculate the time difference in seconds between the onset of one event/block and the next onset of that same condition. Take the maximum difference across all conditions and all subjects, and multiply by 1.5. If the result is smaller than 125 s, use 125 s as your high-pass filter width; otherwise use the calculated value.

Example: a block design with a 30 s experimental block alternating with a 30 s control block has a 60 s onset-to-onset interval. 60 × 1.5 = 90 s, which is below 125 s, so the filter width is 125 s. If some conditions are performance-dependent (and so vary in timing across subjects), use the maximum value observed anywhere in your sample.

2. Install a Container Platform

This step is only needed once per machine.

  1. Open a terminal (on Windows, use Docker Desktop's terminal).
  2. Type apptainer or singularity and press enter. If you get usage instructions rather than “command not found,” you already have a container platform - skip to Section 3.
  3. Only if running on an HPC: try module load singularity (or apptainer) to load it as an optional module. You will need to re-run this every time you log back in or start a new node.
  4. Choose a platform for your system:

3. Download HALFpipe

The Parenting IBMA project uses HALFpipe v1.3.2 (the last release cycle). Check the HALFpipe About page for the current recommended version before you start, since the container is updated periodically.

PlatformCommand
Apptainer / Singularity 3.xcurl -O https://download.fmri.science/singularity/halfpipe-1.3.2.sif

  • If using Apptainer/Singularity: run find $(pwd) -maxdepth 1 to confirm the .sif/.simg file downloaded, and note its full path. You'll need it in Section 4.
  • If using Docker: no file path is needed: Docker stores the image internally.

4. Set Up Your Working Directory

  1. Create an empty base directory with enough free disk space (see Section 1.1), e.g. cd path/to/your_working_sapce; mkdir parenting_ibma.
  2. Create a working directory inside it for HALFpipe's outputs, e.g. mkdir working_dir.
  3. Place a copy of your FreeSurfer license file (license.txt) inside the working directory.
Run HALFpipe once per cohort/site. If your site has more than one scanner or sub-cohort with materially different acquisition parameters (e.g., different TRs), use a separate working directory for each.

5. Run Preprocessing and Feature Extraction

5.1 Launching HALFpipe

Only if running on an HPC: request an interactive job before launching (ask your HPC admins/IT for the exact syntax if these examples don't match your cluster):

SLURMsrun --time 0-6 --ntasks=1 --pty bash
SGEqlogin -now no
Torque / PBSqsub -I -l walltime=12:00:00

Start the container:

ContextCommand
Apptainer/Singularity, HPCapptainer run --contain --cleanenv --bind /:/ext halfpipe-1.3.2.sif --use-cluster
Apptainer/Singularity, local machineapptainer run --contain --cleanenv --bind /:/ext halfpipe-1.3.2.sif --subject-chunks --nipype-n-procs 1 --keep none
Docker, local machine (Mac)docker run --interactive --tty --volume /:/ext halfpipe/halfpipe:1.3.2 --subject-chunks --nipype-n-procs 1 --keep none

5.2 Data Questions

HALFpipe will now open an interactive text UI and ask a series of questions; use Ctrl-C at any point to go back a step.

  1. Specify working directory (the folder created in Section 4).
  2. Is the data available in BIDS format?
    • Yes → enter the path to your BIDS directory and continue to step 6.
    • No → continue with the sub-steps below.
  3. Specify the path of the T1-weighted image files, using the {subject} tag in place of the subject ID (e.g. /path/to/T1/{subject}/T1.nii.gz). * and ? wildcards can stand in for dates or run counters. HALFpipe will report how many files/subjects it found.
  4. Specify the path of the BOLD image files the same way, using {subject} (and {task} if you have more than one task).
  5. Check that the repetition time (TR) values shown are correct for your data. A TR of 1 s is sometimes mis-set in headers created by concatenating 3D volumes, correct this manually if so.
  6. Add more BOLD image files? Say Yes if you need to add data with a different folder structure or metadata (e.g. a different TR), otherwise No.
  7. Do slice timing? Yes if you have the acquisition's slice-timing details (check with your MR physicist/technician if unsure); confirm or correct the detected slice order and timing values. Otherwise No.
  8. Remove initial volumes from scans? Enter 0 unless your data needs equilibration volumes discarded.
  9. Specify field maps? Yes if you acquired them (you'll be asked for their type, file names, and acquisition parameters); this step is skipped automatically for BIDS input. Otherwise No.
  10. Specify first-level features? Select Yes.

5.5 Edge Cases

If your only anatomical images are already skull-stripped

Press Ctrl-C to stop the program before it finishes generating commands. Open spec.json in the working directory in a text editor, find "skull_strip_algorithm": "ants", change "ants" to "none", and save. Restart HALFpipe, select the same working directory, and choose Run without modification when it detects the existing spec file.

If running on an HPC

HALFpipe will generate and validate the commands to run (this can take a few hours for large samples). Once done, it writes submit.slurm.sh, submit.pbs.sh, or submit.sge.sh to the working directory. Open this script and compare the header lines against an example from your HPC's documentation — add any missing directives (e.g., partition/queue name) — then submit it:

SLURMsbatch submit.slurm.sh
SGEqsub submit.sge.sh
Torque/PBSqsub submit.torque.sh

Otherwise, HALFpipe begins processing immediately once you finish answering the prompts.

As soon as you finish specifying all your data, features and models in the user interface, HALFpipe will now generate everything needed to run on the cluster. For hundreds of subjects, this can take up to a few hours. When HALFpipe exits, edit the generated submit script submit.slurm.sh according to your cluster’s documentation and then run it. This submit script will calculate everything except group statistics.

6. Check Pre-Processing and Re-Run If Necessary

Open a terminal, navigate to your working directory, and run:

for i in $(strings graphs.*.dat | grep features_wf | grep result_make_resultdicts_b.pklz | sed 's|^/ext||g'); do
  if [ ! -f ${i} ]; then
    echo ${i} | sed "s/^.*single_subject_\([A-Za-z0-9]*\)_wf.*$/\1/p";
  fi;
done | sort | uniq | tee subject-list.txt

This prints any subjects that did not finish processing and writes their IDs to subject-list.txt in the working directory (you can also hand-edit this file, e.g. to add newly arrived participants).

  • If not on HPC: re-run HALFpipe with the same command as before, adding --subject-list <full path to subject-list.txt> at the end, then select Run without modification.
  • If on HPC: add the same option to your submission script and resubmit.
  • You can also use --subject-include <characters> to (re-)run only subjects whose ID contains those characters.

7. Quality Assessment

  • If you ran on an HPC, copy the reports folder from your working directory to a machine where you can comfortably review it.

Complete the QC ratings using the HALFpipe quality-control guide.

  • Contact the coordinating site if you're unsure about a particular image and can't resolve it with a local scanner technician/MR physicist.

8. Group-level Analysis

  • After confucting QC, you can run group statistics. This is usually very fast, so you can do this in an interactive session. Run singularity run --containall --bind /:/ext halfpipe-1.3.2.sif --only-model-chunk and then select Run without modification in the user interface..

9. Submitting Your Site's Results for the IBMA

Once preprocessing, first-level modeling, and your group-level model(s) from Section 5.4 have completed and passed QC:

  1. Locate the group-level summary statistic (contrast) maps in the grouplevel folder of your working directory, one set per model you specified.
  2. Package the summary maps together with a brief note specifying which subscale(s) you used for each construct (according to your confirmed Site Confirmation Packet mapping), the models you conducted in the HALFpipe pipeline, the sample size after QC, and demographic characteristics (e.g., mean age [M (SD)], biological sex (N), etc.).
  3. Please also provide the name, educational degree, affiliation, address, and email address of the person/people who conducted the analysis and the project leader, as they will be included as co-authors on the manuscript.
  4. Send these to the coordinating site for pooling into the meta-analysis, following the data-transfer method the coordinating team has specified for this project.
